# Locat complete feature and historical requirements matrix

Audit date: 2026-10-11. Baseline: `feat/locat-unified-platforms` at `b849774` (application tree `af63b2c`). Development changes listed as in progress are not part of the baseline. This is a canonical evidence register, not a release-completion claim.

## Status meanings and provenance

- **Planned:** approved requirement, no integrated implementation found.
- **Scaffolded:** contracts/adapters/demo or preserved engine only, no complete runtime flow.
- **Partial:** integrated subset, with explicitly listed missing scope.
- **Implemented:** runtime path present; acceptance may remain open.
- **Tested:** related automated tests were passed in recorded baseline CI; scope is limited to those assertions. Listed test names identify evidence locations and may cover adjacent behavior rather than every acceptance condition.
- **Historical device accepted:** the original numbered ledger records user acceptance of that item on an older build. This does not accept the new unified APK/desktop application. No unified physical acceptance is claimed.

Every original row is sourced from `docs/LOCAT-1.0-PLAN.md`: original 01–41, approved additions 42–43, Android addition 44, attachment/location expansion 45–49. Earliest plan commit is `c73b023`; later original additions are preserved in that file's git history. Original numbering is preserved below. The plan's top backlog lists 45–49 before 42–44, but the later sections recover the missing IDs.

The numbered ledger accepts **01,03,06,07,17,41**. `docs/PROJECT-HISTORY-AND-HANDOFF.md` also records a historical **13/44** conversational counter, explicitly warns it is not an audited per-item ledger, and reports cross-account Android/Firefox messaging and a signed APK upgrade. We preserve this evidence without guessing which seven additional numbered items it represents. Physical acceptance must be re-established for current builds.

### Shared dependencies used by every row

**Security:** preserve existing authenticated encrypted envelopes, key recovery, current membership/ownership, strict HTTPS, bounded inputs, account/server isolation, safe logging and storage. Additional feature-specific boundaries are included in Remaining work.

**Platforms:** each user-facing row targets web/PWA, Capacitor Android and Tauri Windows/Linux/macOS; browser capability or CI packaging alone is not native-device acceptance. Microphone, notifications, codecs, storage, background behavior, share targets and biometrics require platform-specific verification. The common manual acceptance suite is `docs/UNIFIED_PLATFORM_TESTING.md`; each row below adds feature-specific acceptance.
